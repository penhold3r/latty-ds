# Tree-shaking Plan: Icons and Components

## Problem Statement

Today any consumer who imports a single Latty component gets all 150 icons bundled
(~73 KB raw SVG data) plus all 44 components. Two root causes:

1. **Icons**: 18 components do `import '@latty/icons'` — a side-effect that runs
   `iconRegistry.registerIcons(lattyIcons)` and bulk-registers every icon.

2. **Components**: `@latty/web` declares `"sideEffects": true` and exports all 44
   components from one barrel. Any import from the package pulls in everything.

No external consumers exist yet — clean break, no migration needed.

## Goal

```ts
// pay only for what you import
import '@latty/web/button'; // just lt-button + its internal deps
import '@latty/icons/xmark'; // just the xmark SVG, registered in the registry
import '@latty/icons/plus'; // just the plus SVG

// barrel still works for dev convenience and the docs site
import '@latty/web'; // all 44 components (no icons)
```

One module per icon, one module per component. No intermediate groupings.

---

## Design

### Icons package

**Bare `@latty/icons`** — registers `lt-icon` custom element, exposes registry and
types. No icon SVG data loaded.

```ts
// packages/icons/src/index.ts
export { Icon } from './components/icon';
export { iconRegistry } from './registry/icon-registry';
export type { LattyIconName, IconDefinition, IconSize } from './types/icons.types';
```

**Per-icon entries** — each self-registers one icon as a side effect:

```ts
// packages/icons/src/entries/xmark.ts  (generated)
import { iconRegistry } from '../registry/icon-registry';
import { xmarkSvg } from '../icons/actions/xmark';
iconRegistry.registerIcon('xmark', xmarkSvg);
```

**`package.json` exports** (generated by build script):

```json
{
  "exports": {
    ".":       { "types": "./dist/index.d.ts", "default": "./dist/index.js" },
    "./xmark": { "default": "./dist/entries/xmark.js" },
    "./plus":  { "default": "./dist/entries/plus.js" },
    ...
  },
  "sideEffects": ["./dist/entries/*.js"]
}
```

### Components package

**Per-component entries** already exist (`dist/components/*/index.js`). Only need the
`exports` map added to `package.json` (generated by build script).

Components stop importing `@latty/icons` entirely. They import only `'../icon/icon'`
to register the `lt-icon` custom element — no SVG data.

**`package.json` exports** (generated by build script):

```json
{
  "exports": {
    ".":            { "types": "./dist/index.d.ts", "default": "./dist/index.js" },
    "./button":     { "default": "./dist/components/button/index.js" },
    "./icon-button":{ "default": "./dist/components/icon-button/index.js" },
    ...
  },
  "sideEffects": ["./dist/index.js", "./dist/components/*/index.js"]
}
```

The barrel `dist/index.js` no longer imports icons. Consumers who want icons load
them explicitly alongside components.

## Implementation Steps

### Step 1 — Strip icon registration from `@latty/icons` entry

- Remove `iconRegistry.registerIcons(lattyIcons)` from `packages/icons/src/index.ts`
- Add `iconRegistry.registerIcon(name, svg)` single-icon method to the registry
  (if it doesn't exist already)

### Step 2 — Generate per-icon entry files

- New script `packages/icons/scripts/build-entries.mjs`:
  - Reads all icon source files from `src/icons/**/*.ts` (excluding `index.ts`)
  - Generates `src/entries/<name>.ts` for each icon
  - Writes the `exports` map + `sideEffects` into `package.json`
- Wire into `packages/icons/package.json` build script
- Add generated `src/entries/` to `.gitignore` (build artifact)

### Step 3 — Strip `import '@latty/icons'` from components

Replace every `import '@latty/icons'` in 18 component files with
`import '../icon/icon'`. Components that don't directly render `<lt-icon>` in their
own template (they use it via a child component) can drop the icon import entirely.

### Step 4 — Generate per-component exports map for `@latty/web`

- Extend `packages/web/scripts/build-manifest.mjs` to also write the `exports`
  field and `sideEffects` into `packages/web/package.json` by scanning
  `dist/components/*/index.js`
- Update `"sideEffects"` to the precise list

### Step 5 — Update docs and examples

The docs dev server and example HTML pages currently rely on bulk-importing everything.
Update to the explicit pattern:

```ts
import '@latty/web'; // components (no icons bundled)
import '@latty/icons/xmark'; // per icon, as needed
```

Or for the full docs experience, enumerate all icons used across all pages in one
entry file.

## Files to create / modify

| Path                                       | Action                                               |
| ------------------------------------------ | ---------------------------------------------------- |
| `packages/icons/src/index.ts`              | Remove `registerIcons` call                          |
| `packages/icons/src/entries/`              | New directory, generated by build script             |
| `packages/icons/registry/icon-registry.ts` | Add `registerIcon(name, svg)` method                 |
| `packages/icons/scripts/build-entries.mjs` | New: generates entry files + exports map             |
| `packages/icons/package.json`              | Updated exports + sideEffects (by build script)      |
| 18× component `.ts` files                  | `@latty/icons` → `../icon/icon`                      |
| `packages/web/src/index.ts`                | Remove any icon import (none currently, stays clean) |
| `packages/web/scripts/build-manifest.mjs`  | Also writes exports map to package.json              |
| `packages/web/package.json`                | Updated exports + sideEffects (by build script)      |
| Docs/examples entry points                 | Explicit per-icon imports                            |

---

## Sequence

All steps ship together in one PR — Steps 1–3 are co-dependent (icons and components
must move together or the registry has no icons at runtime). Steps 4–5 are independent
but low-risk enough to bundle in the same PR.
