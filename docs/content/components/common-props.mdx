# Common Props

Most Latty components share a set of conventions. This page documents them once — individual component pages cover what's unique.

## Size

Many components accept a `size` attribute with consistent values: `sm`, `md` (default), and `lg`.

<FrameworkTabs
  html={`<lt-button size="sm">Small</lt-button>
<lt-button size="md">Medium</lt-button>
<lt-button size="lg">Large</lt-button>`}
  react={`import { Button } from '@latty-ds/react';

<Button size="sm">Small</Button>
<Button size="md">Medium</Button>
<Button size="lg">Large</Button>`}
  vue={`<lt-button size="sm">Small</lt-button>
<lt-button size="md">Medium</lt-button>
<lt-button size="lg">Large</lt-button>`}
/>

**Components with `size`:** `lt-avatar`, `lt-badge`, `lt-button`, `lt-checkbox`, `lt-chip`, `lt-color-input`, `lt-combobox`, `lt-date-input`, `lt-datepicker`, `lt-dialog`, `lt-icon-button`, `lt-list`, `lt-pagination`, `lt-progress`, `lt-radio`, `lt-select`, `lt-slider`, `lt-spinner`, `lt-switch`, `lt-tab`, `lt-tab-group`, `lt-textfield`.

:::note
Most components use `sm | md | lg`. Exceptions: `lt-dialog` adds `xl` and `fullscreen`; `lt-avatar` adds `xs` and `xl`.
:::

## Variant

Semantic color variants convey meaning — primary for emphasis, error for destructive actions, success for confirmation. The available set depends on the component's role.

**Form inputs** use validation-focused variants:

`default` · `success` · `warning` · `error`

**Action and display components** use the full semantic palette:

`primary` · `secondary` · `neutral` · `success` · `warning` · `error` · `info`

:::caution
There is no `danger` variant. Use `variant="error"` for destructive actions.
:::

## Appearance

Controls the visual weight of a component independently of its color variant.

| Appearance | Description | Used by |
|------------|-------------|---------|
| `filled` | Solid background (default for most) | button, alert, chip, snackbar, surface |
| `outlined` | Bordered, transparent background | button, alert, accordion, chip, surface |
| `ghost` | No border or background, just text/icon | button |
| `solid` | High-contrast filled background | alert |
| `clean` | Minimal, no visual container | accordion |

## Labels (i18n)

Components with built-in UI text (close buttons, validation messages, navigation labels) accept a `labels` property for internationalization. It's a JS-only property — set it via JavaScript or a framework binding, not as an HTML attribute.

Each component defines its own `Labels` interface with English defaults. Override only the keys you need:

<FrameworkTabs
  html={`<lt-calendar id="cal"></lt-calendar>

<script>
  document.getElementById('cal').labels = {
    today: 'Hoy',
    previousMonth: 'Mes anterior',
    nextMonth: 'Mes siguiente'
  };
</script>`}
  react={`import { Calendar } from '@latty-ds/react';

<Calendar
  labels={{
    today: 'Hoy',
    previousMonth: 'Mes anterior',
    nextMonth: 'Mes siguiente',
  }}
/>`}
  vue={`<lt-calendar
  :labels="{
    today: 'Hoy',
    previousMonth: 'Mes anterior',
    nextMonth: 'Mes siguiente'
  }"
></lt-calendar>`}
/>

**Components with `labels`:** `lt-alert`, `lt-breadcrumb`, `lt-calendar`, `lt-checkbox`, `lt-chip`, `lt-color-input`, `lt-combobox`, `lt-date-input`, `lt-dialog`, `lt-link`, `lt-pagination`, `lt-radio`, `lt-select`, `lt-sidepanel`, `lt-snackbar`, `lt-snackbar-group`, `lt-switch`, `lt-tab-group`, `lt-table`, `lt-textfield`.

Each component's API table lists its full `Labels` interface with defaults.

## Native form association

Form-capable components use the browser's `ElementInternals` API to participate in native `<form>` submission. This means they:

- Report their value via `FormData` when the form is submitted
- Support native constraint validation (`required`, `pattern`, `min`, `max`)
- Respond to `form.reset()` and browser-initiated state restoration
- Work with `<form>` without any JavaScript glue

<FrameworkTabs
  html={`<form id="signup">
  <lt-textfield name="email" label="Email" required type="email"></lt-textfield>
  <lt-select name="role" label="Role" required></lt-select>
  <lt-checkbox name="terms" label="I agree to the terms" required></lt-checkbox>
  <lt-button type="submit">Submit</lt-button>
</form>

<script>
  document.getElementById('signup').addEventListener('submit', (e) => {
    e.preventDefault();
    const data = new FormData(e.target);
    console.log(Object.fromEntries(data));
    // { email: "user@example.com", role: "admin", terms: "on" }
  });
</script>`}
  react={`import { Textfield, Select, Checkbox, Button } from '@latty-ds/react';

function SignupForm() {
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    const data = new FormData(e.currentTarget);
    console.log(Object.fromEntries(data));
  };

  return (
    <form onSubmit={handleSubmit}>
      <Textfield name="email" label="Email" required type="email" />
      <Select name="role" label="Role" required />
      <Checkbox name="terms" label="I agree to the terms" required />
      <Button type="submit">Submit</Button>
    </form>
  );
}`}
  vue={`<template>
  <form @submit.prevent="handleSubmit">
    <lt-textfield name="email" label="Email" required type="email"></lt-textfield>
    <lt-select name="role" label="Role" required></lt-select>
    <lt-checkbox name="terms" label="I agree to the terms" required></lt-checkbox>
    <lt-button type="submit">Submit</lt-button>
  </form>
</template>

<script setup>
function handleSubmit(e) {
  const data = new FormData(e.target);
  console.log(Object.fromEntries(data));
}
</script>`}
/>

**Form-associated components:** `lt-textfield`, `lt-select`, `lt-checkbox`, `lt-radio`, `lt-switch`, `lt-slider`, `lt-color-input`, `lt-combobox`, `lt-date-input`, `lt-datepicker`.

All extend `FormControlElement` which calls `attachInternals()` and manages `setFormValue()`, `formResetCallback()`, and `formStateRestoreCallback()` automatically.

## Imperative methods

Overlay components expose `show()`, `hide()`, and `toggle()` methods as an alternative to setting the `open` attribute:

<CodeBlock language="js">{`const dialog = document.querySelector('lt-dialog');

// These are equivalent:
dialog.open = true;
dialog.show();

// And these:
dialog.open = false;
dialog.hide();

// Toggle between open and closed:
dialog.toggle();`}</CodeBlock>

**Components with `show()` / `hide()` / `toggle()`:** `lt-dialog`, `lt-sidepanel`.

`lt-dropdown` manages its own open state through the trigger element, but the same methods are available for programmatic control.

## CSS custom properties

Every component exposes `--lt-[component]-[property]` CSS custom properties for contextual overrides. Set them on the element or any ancestor — they inherit through the shadow DOM.

<CodeBlock language="css">{`/* Override button styles in a specific context */
.site-header {
  --lt-button-bg: transparent;
  --lt-button-color: white;
  --lt-button-min-width: 0;
}

/* Custom progress bar color */
.upload-progress {
  --lt-progress-color: #8b5cf6;
  --lt-progress-height: 8px;
}`}</CodeBlock>

## CSS shadow parts

Components expose named `::part()` targets so you can style specific internal elements from outside the shadow DOM.

<CodeBlock language="css">{`/* Style the inner button element */
lt-button::part(base) {
  text-transform: uppercase;
  letter-spacing: 0.05em;
}

/* Style the tooltip bubble */
lt-tooltip::part(tooltip) {
  max-width: 320px;
}

/* Style the dialog overlay surface */
lt-dialog::part(surface) {
  border-radius: 16px;
}`}</CodeBlock>

## Boolean HTML attributes

Boolean attributes in HTML follow the standard: **presence means true, absence means false**. Never set a boolean attribute to the string `"false"` — it's still truthy.

<CodeBlock language="js">{`// ✗ This keeps the element disabled (attribute is present, value ignored)
el.setAttribute('disabled', 'false');

// ✓ Remove the attribute to disable it
el.removeAttribute('disabled');
// or set the JS property
el.disabled = false;`}</CodeBlock>

This applies to `disabled`, `required`, `checked`, `open`, `animated`, `dismissible`, `loading`, and all other boolean props.
