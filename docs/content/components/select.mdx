# Select

A custom dropdown with labels, placeholder, helper text, and validation states. The <code>options</code> property is set
via JavaScript as an array of <code>&#123; value, label &#125;</code> objects.

Each option may also include an optional <code>group</code> (groups a contiguous run of options under one
heading, like a native <code>&lt;optgroup&gt;</code>), <code>icon</code>, and <code>description</code>.

## Select vs. Dropdown

Both let the user choose from a list of options, but they are built for different purposes:

<table className="compare-table" aria-label="Select vs. Dropdown comparison">
  <thead>
    <tr>
      <th scope="col" aria-label="Property"></th>
      <th>Select</th>
      <th>Dropdown</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>
        <strong>Trigger</strong>
      </td>
      <td>A styled form field with a label and helper text</td>
      <td>Any slotted element — button, icon, avatar</td>
    </tr>
    <tr>
      <td>
        <strong>Options</strong>
      </td>
      <td>
        <code>options</code> prop — array of <code>&#123; value, label &#125;</code>, with optional
        <code>group</code>, <code>icon</code>, and <code>description</code>
      </td>
      <td>
        Fully custom slot content (<code>lt-dropdown-item</code>)
      </td>
    </tr>
    <tr>
      <td>
        <strong>Use when</strong>
      </td>
      <td>Form fields — the user is selecting a value that will be submitted or stored</td>
      <td>Action menus, context menus, overflow menus — the user is choosing an action, not setting a value</td>
    </tr>
    <tr>
      <td>
        <strong>Avoid when</strong>
      </td>
      <td>You need fully custom item layouts beyond a label/description/icon, or the trigger isn't a form field</td>
      <td>You need the selected value to persist or participate in form submission — use Select instead</td>
    </tr>
  </tbody>
</table>
