# AGENTS.md

Latty is a pnpm-workspace design system. `tokens.config.json` generates CSS/JSON/JS token outputs, Lit Web Components (`lt-*`) consume `--lt-*` variables, React wrappers are generated from the web manifest, and a Docusaurus site documents it all. Public packages are `@latty-ds/{tokens,web,icons,react}`; `@latty-ds/utils` and the docs site are private.

Use Node 24 + pnpm 9. `CLAUDE.md` is the long-form contributor reference — keep it, `GEMINI.md`, and this file aligned when commands or conventions change.

## Commands

```bash
pnpm install
pnpm dev                  # build tokens + web manifest, then docs on :3000
pnpm docs:dev             # docs only; skips token/manifest prebuilds
pnpm build                # every workspace, including docs
pnpm exec vitest run      # one-shot tests; `pnpm test` opens watch mode in a terminal
pnpm exec vitest run packages/web/src/components/button/__tests__/button.test.ts
pnpm exec vitest run -t "reflects %s variant"   # single test by name
pnpm lint
pnpm typecheck
pnpm check:boundaries
pnpm check:esm-smoke
pnpm format:check         # or pnpm format
pnpm a11y                 # builds + serves docs, then Playwright/axe
pnpm bundle-size          # add :update to rewrite the committed baseline
pnpm release:notes        # print the GitHub release notes for a version (default: current tag)
```

`pnpm build` also builds the docs; CI uses `pnpm --filter './packages/**' -r build` when only packages are needed.

After `pnpm clean` (or on a fresh clone), run `pnpm build` before tests, `typecheck`, or `check:esm-smoke`: React tests import the built package, while typecheck and the ESM smoke check resolve `dist`. Docs also import `@latty-ds/web` from `dist`, so build once before `pnpm dev`. Full verification order: build → test → lint → format:check → typecheck → check:boundaries → check:esm-smoke → a11y.

## Repository map

- `packages/tokens` — `tokens.config.json` → `dist/tokens.css`, `semantic.css`, `tokens.json`, `tokens.js`, plus browser `configure()`/`createStyleSheet()`.
- `packages/web` — Lit components under `src/components/<name>/`; the component folder owns its `.ts`, `.styles.ts`, `.types.ts`, `index.ts`, and `__tests__/`.
- `packages/icons` — icon registry; the build generates `src/entries/` (gitignored) and `dist/`.
- `packages/react` — wrappers generated from `packages/web/custom-elements.json`.
- `packages/utils` — private build-time helpers, including the `logger`.
- `docs` — Docusaurus app; MDX lives in `docs/content/`, not `docs/docs/`.
- `agents` — consumer-facing AI context pack, not contributor guidance.
- `scripts` — wrapper codegen, boundary/ESM checks, bundle-size reporting.

## Change workflows

Scaffolding commands are plain bash scripts in `.claude/commands/`; run them directly without Claude Code:

```bash
bash .claude/commands/new-component.sh Card --variants primary,neutral --sizes sm,md --disabled --events change
bash .claude/commands/new-token.sh color purple '#a855f7'
bash .claude/commands/new-icon.sh navigation compass
```

`new-component` creates the component, test, docs page, gallery entry, `src/index.ts` export, and rebuilds `@latty-ds/web`. `new-token` updates `COLOR_NAMES` and `tokens.config.json`. Do not hand-create these files or hand-edit `tokens.config.json` for a new colour.

After changing a component’s public props/events, regenerate the manifest and wrappers:

```bash
pnpm --filter @latty-ds/web build
pnpm codegen:wrappers
pnpm --filter @latty-ds/react build
```

`packages/web/custom-elements.json` is committed and regenerated by the web build. The web build also regenerates the per-component `exports` map in `packages/web/package.json`; do not maintain those subpaths by hand. `packages/react/src/components/**` and `packages/react/src/index.ts` are generated — only edit files that start with `// codegen:manual`.

When the public component catalog changes, update the consumer pack in `agents/` (`components.md`, `decision-guide.md`, `theming.md`, etc.) in the same change. Planning notes, audits, and research belong in gitignored `_agent-plans/` using `SCREAMING-KEBAB.md` names.

## Conventions and traps

- Components extend `ThemeableElement` from `packages/web/src/base`. Keep the default slot inside a single `.content` wrapper (`<span class="content"><slot></slot></span>`) with `min-width: 0`; a bare slot inside flex/grid fragments rich slotted content.
- Component styles must use semantic tokens (`--lt-text-*`, `--lt-bg-*`, `--lt-border-*`, `--lt-interactive-*`). A lint ratchet rejects new raw palette steps (`var(--lt-color-*-N)`) and literal `rgb()`/`rgba()` in `*.styles.ts`; lower the per-file baseline in `eslint-rules/no-raw-component-colors.mjs` when fixing one.
- Package boundaries: relative imports within a package, `@latty-ds/*` package names across packages. Never use `../` to leave a package root.
- Tests run in jsdom. `vitest.setup.ts` registers every icon globally and stubs browser APIs jsdom lacks (dialog, popover, `ResizeObserver`, `matchMedia`, scrolling, pointer capture, form internals) — extend those stubs rather than recreating them per test.
- Lit updates are async: `await el.updateComplete` before asserting on the DOM or shadow root. Use `it.each([...] as const)` for variants/sizes instead of loops inside one test; `vitest/prefer-each` enforces the related pattern.
- Docs pages are auto-routed from `docs/content/**` and the sidebar is autogenerated in `sidebars.ts`; there is no sidebar array to edit. Component pages use `ComponentPlayground` and `ApiTable`, which read `packages/web/dist/manifest.json` — restart `pnpm dev` after a public API change so the manifest rebuilds. The docs site must demonstrate Latty components, including swizzled Docusaurus chrome under `docs/src/theme/`.
- `no-console` is an error. Use `logger` from `@latty-ds/utils` in scripts.
- TypeScript 6: emitting tsconfigs must set `rootDir`; tsup `dts` builds and `docs/tsconfig.json` need `"ignoreDeprecations": "6.0"`; Node globals are not auto-included, so add `"types": ["node"]` where needed.
- Prettier: 120 columns, single quotes, no trailing commas. Commits use Conventional Commits with scopes `tokens|web|icons|react|utils|docs|scripts|deps|config|ci|release`; `pre-push` runs boundaries, typecheck, lint, and tests.
